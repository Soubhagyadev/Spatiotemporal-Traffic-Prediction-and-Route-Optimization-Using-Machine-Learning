What this system is

The portal turns the Part 1 machine-learning pipeline into a browsable, queryable service. A Flask API exposes the cleaned traffic database and the trained speed models as JSON; this Django application renders that API as dashboards, segment pages and on-demand forecasts.

Congestion labels follow the thresholds derived from the training period (< {{ thresholds.high_congestion_below_mph|default:"31.53" }} mph is High, ≥ {{ thresholds.low_congestion_above_mph|default:"48.05" }} mph is Low, everything between is Medium), so every label on this site is directly comparable with the model report.

Architecture

LayerTechnologyRole
Model + data APIFlask (port 5001)Reads the SQLite/Parquet outputs, serves links, congestion, metrics and predictions as JSON.
Web interfaceDjango (this app)Server-rendered dashboards, segment explorer, forecast form.
Analyst dashboardDashInteractive cross-filtering for exploratory analysis.

This Django layer holds no models and no database tables: it is a presentation client of the API, with a cached HTTP client and graceful degradation when the API is down.

Static reports

  • /reports/validation_report.md — data-quality checks on the raw and clean tables.
  • /reports/model_report.md — baseline and model comparison, coefficients, diagnostics.

These files live in the repository under reports/ and are not served by this app.
